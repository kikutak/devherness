# ADR-0004: レビュー判断とマージ実行を別jobに分離する

## Status

Accepted (2026-08-13)

## Context

本ループは完全自動(人間の承認ゲートなし)で、レビューが承認されたMRはそのまま自動でマージされる。この際、「レビューの合否を判断する処理」と「実際にマージを実行する処理」を同一のClaude Codeエージェント(レビュー役)に持たせるか、別のjobに分離するかを検討する必要がある。

マージは不可逆に近い操作(履歴に残り、mainブランチに変更を取り込む)であり、Claude Codeエージェントの判断にはハルシネーションや誤判定のリスクが皆無ではない。また、将来的に人間承認ゲートを段階的に追加/削除したいという要件([設計ドキュメント 10章](../design/multi-agent-dev-loop.md#10-将来の拡張余地))もある。

## Decision

レビュー役(Claudeによる合否判断・MRコメント投稿・`state::approved`ラベル付与)と、実際のマージ実行(`merge-gate` job、GitLab Merge APIを直接呼び出す決定論的スクリプト、Claude非依存)を**別jobに分離**する。レビュー役は判断結果をラベルとTrigger API呼び出し(`LOOP_PHASE=merge`)で`merge-gate`に引き渡すのみとし、マージ操作自体のツール・権限は持たない。

詳細は [設計ドキュメント 7章](../design/multi-agent-dev-loop.md#7-マージの分離) を参照。

## Consequences

**メリット**
- 「レビューの合否判断」と「マージという不可逆操作の実行」の権限・責務が分離され、レビュー役の誤判定/ハルシネーションが直接誤マージに直結するリスクを下げられる。
- マージ実行トークンをレビュー役トークンとは別に発行でき、[設計ドキュメント 9章](../design/multi-agent-dev-loop.md#9-セキュリティ権限設計)の最小権限方針に合致する。
- `merge-gate`に`when: manual`を追加するだけで、将来的に人間承認ゲートを挿入できる(段階的な自律度の引き上げ/引き下げが容易)。

**デメリット・トレードオフ**
- jobがひとつ増える分、パイプライン全体の実行時間・複雑さがわずかに増す。
- レビュー役の判断結果(承認/却下)を`merge-gate`へ正しく引き渡すための状態受け渡し([ADR-0002](0002-state-management-labels-and-repo-file.md))の整合性維持が必要になる。
