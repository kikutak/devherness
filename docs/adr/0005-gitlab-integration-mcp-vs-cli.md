# ADR-0005: GitLab連携をMCPサーバとCLI/API直叩きのハイブリッドにする

## Status

Accepted (2026-08-13)

## Context

各ロールのClaude Codeエージェントは、MRコメント投稿・ラベル操作・MR取得・Issue作成・パイプライントリガーといったGitLab操作を行う必要がある。実現手段として主に以下の三つが考えられる。

| 方式 | 長所 | 短所 |
|---|---|---|
| `glab` CLI / 素のcurl | セットアップ簡単、CI job内で完結、依存少 | ツール粒度の権限制御がしづらい(Bashが全部見える)、構造化された監査が弱い |
| GitLab REST API直叩き | 柔軟、CI変数だけで完結 | プロンプト側で毎回API仕様を記述する必要、エラー処理の再実装 |
| GitLab MCPサーバ | Claude Codeの`allowedTools`でツール単位に権限を絞れる(例: コメント投稿は許可するがマージは不許可)、構造化された呼び出しで監査しやすい | MCPサーバのビルド・保守・コンテナ配布のコストが増える |

いずれか単一の方式に統一すると、以下の問題が生じる。
- CLI/API直叩きのみにすると、Bashコマンド経由でエージェントがGitLabリソースに対して意図しない広い権限を行使できてしまう(プロンプトインジェクション耐性が低い)。
- MCPサーバのみにすると、マージ実行やTrigger API呼び出しのような「Claudeの判断を必要としない決定論的操作」までLLMの呼び出しを経由することになり、不要なコスト・ハルシネーションリスクを負う。

## Decision

操作の性質によって手段を使い分けるハイブリッド構成を採用する。

- **Claudeの判断が必要な操作(コメント投稿、レビューコメントの内容決定、ラベル判断)**: GitLab MCPサーバ経由で実行する。MCP設定でツールを「コメント投稿」「ラベル操作」「MR/Issue取得」等に限定し、**マージ操作ツールは意図的にMCP設定から除外**する。
- **決定論的な操作(マージ実行、Pipeline Trigger API呼び出し)**: Claude Codeを介さず、シェルスクリプト(`ci/*.sh`)で直接GitLab REST APIを叩く。
- **コード変更を伴うコーディング役**: GitLab連携よりgit操作が主体のため、素の`git`/Bashで十分とする。

詳細は [設計ドキュメント 8章](../design/multi-agent-dev-loop.md#8-gitlab連携方法) を参照。関連: [ADR-0004](0004-merge-gate-separation.md)(マージ実行を決定論的スクリプトに分離する判断はこのADRの前提の一部)。

## Consequences

**メリット**
- ロールごとにツール粒度で権限を絞れるため、[設計ドキュメント 9章](../design/multi-agent-dev-loop.md#9-セキュリティ権限設計)で定めたプロンプトインジェクション対策(悪意あるIssue/MRコメントが権限外操作を引き起こせないようにする)が実効的になる。
- マージ・Trigger APIのような不可逆・重要操作をLLMの判断から切り離すことで、誤動作リスクとAPIコストを削減できる。
- MCP呼び出しは構造化されるため、監査ログとして扱いやすい。

**デメリット・トレードオフ**
- GitLab MCPサーバの選定・構築・コンテナ配布・バージョン管理という保守コストが新たに発生する。
- 「どの操作をMCP経由にし、どの操作をスクリプト直叩きにするか」の切り分け基準をロール追加のたびに見直す必要があり、設計判断の属人化を避けるため本ADRのように明文化しておく必要がある。
